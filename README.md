# GPExit — Google Photos Exit

GPExit turns Google Photos Takeout ZIP files into a cumulative archive of photos and videos, organized by year and month. You can import new Takeout exports alongside annual ZIP files produced by GPExit, then create updated annual ZIP files with optional AES-256 encryption.

## Requirements

- Python 3.10 or newer
- macOS, Linux, or Windows
- Enough free disk space for the extracted files and, optionally, annual ZIP files

## Install

Create a virtual environment from the project directory:

```sh
python -m venv .venv
```

Activate it on macOS or Linux:

```sh
source .venv/bin/activate
```

Or on Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Then install the dependencies:

```sh
python -m pip install -r requirements.txt
```

## Use

1. Create an `inputs` folder in the project directory and place your Takeout ZIP files inside it. You may also include annual ZIP files previously generated by GPExit.
2. Run:

   ```sh
   python gpexit.py
   ```

3. Enter passwords when requested. GPExit reuses the last successful password and asks again if it does not work for another archive.
4. Choose whether to create annual ZIP files and whether to protect them with an AES-256 password.

The output looks like this:

```text
output/
├── 2023/
│   ├── 01/
│   │   ├── photos/
│   │   └── videos/
│   └── Unknown month/
│       └── photos/
├── Unknown year/
│   └── Unknown month/
│       └── photos/
└── archives/
    ├── 2023.zip
    └── Unknown year.zip
```

On later runs, GPExit keeps the existing output and adds new files. To rebuild from annual ZIP files alone, place them in `inputs` with the new Takeout exports. Input ZIP files are never modified.

To select ZIP files or an output directory explicitly:

```sh
python gpexit.py inputs/first.zip inputs/second.zip --output ../photo-archive
```

By default GPExit uses up to four worker processes, based on available CPUs. Change this with `--workers`:

```sh
python gpexit.py --workers 2
```

## Dates and duplicates

GPExit uses Google's `photoTakenTime` first, then a full date recognized in the filename. It can also use the original EXIF date of images supported by Pillow. Previously generated annual archives supply their stored year and month when other dates are unavailable. ZIP creation and modification dates are not used. Video metadata embedded in the file is not read.

Files with unknown dates go under `Unknown year/Unknown month`; files with a known year but unknown month go under `Unknown month`. Earlier GPExit output using the old year/type layout is migrated to the monthly layout on the next run. Older annual ZIP files can still be imported.

Files with identical SHA-256 hashes are treated as duplicates, even if their names differ. Different files with the same name receive a hash suffix. If a later copy supplies a missing date, GPExit can move the existing file into the corresponding folder. Filenames are adjusted where needed to work across common operating systems.

Google JSON metadata is associated by its `title` or matching sidecar filename and archive folder across the ZIP files supplied in the same run, and matching JSON is saved alongside the media. If multiple JSON files have the same key, the first is used. Metadata that cannot be matched is not copied. GPExit imports the photo and video extensions listed in `gpexit.py`; other files are reported and skipped. Original album folders are not recreated.

## Disk usage and passwords

GPExit reads ZIP files without extracting them in full first. It uses up to one temporary media file per worker. Annual ZIP files are created one at a time and stored without additional compression because media is generally already compressed. Updating an existing annual ZIP temporarily requires space for both its old and new versions. Neither the original inputs nor the extracted output are deleted.

Passwords are kept in memory during the run and are not stored by GPExit. Keep your archive password safe: GPExit cannot recover it. AES-encrypted ZIP files require compatible extraction software, such as 7-Zip.

Press **Ctrl+C** to stop an import; completed files remain in the output. Run the same command again to resume. GPExit stores progress in `output/.gpexit-progress.sqlite3` and skips completed files that are still present and unchanged. Keep that file with the output directory. Progress from versions without checkpoints cannot be reconstructed, so the first run after upgrading rechecks earlier imports through deduplication.

Each run hashes all input ZIP contents and checks existing output files before resuming. This takes time and reads disk space but avoids trusting filenames or modification dates. If the ordered list of input paths or any ZIP content changes, GPExit reprocesses the inputs and deduplicates against the existing output. Never run two instances against the same output directory. Keep the original exports until you have verified the resulting archive.

## Development

```sh
python -m unittest discover -s tests -v
```

The ZipCrypto integration test requires the `zip` command and is skipped when it is unavailable. Other tests use generated fixtures and do not need personal exports.

The default `inputs` and `output` folders and ZIP files are ignored by Git. If you choose a custom output directory inside the repository, add it to `.gitignore` before publishing: unrecognized files and metadata could otherwise be included.
